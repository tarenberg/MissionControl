3. **Real-time Synchronized Chat State Preservation**:
   - Diagnosed why user messages (optimistic user turns) were "not appearing" or vanishing inside the VAT Chat message window.
   - The culprit was our multi-device real-time synchronization polling engine running on a short `1500ms` interval inside `/chat` (`app/chat/page.tsx`).
   - During active voice or text submissions (which undergo local Whisper STT or Ollama gemma2 generation steps taking several seconds), the background polling loop was overwriting the active React `messages` state with the database contents before the message was fully completed and saved, instantly wiping the user's optimistic bubble from the screen.
   - Corrected this by modifying the polling logic to strictly check the `isThinking` flag. When the client is actively submitting/generating a message turn (`isThinking: true`), the interval bypasses database fetching, holding and protecting the user's optimistic turn safely on the screen until the assistant response resolves and commits to SQLite.

4. **Live Voice Parallel STT & Default Room Sync**:
   - **Discovered Deep Room Desynchronization:** Realized that the floating popup (`ChatPopupV3.tsx`) was communicating with a default `'Muffin'` database room, while the standalone page `/chat` (`app/chat/page.tsx`) was looking for and displaying `'Muffin 🧁'` (with the emoji). Since these were two separate rooms in the database with completely different IDs, messages sent in the popup never showed up on `/chat`, and vice versa. Fully resolved this by synchronizing the default popup room fetch to `'Muffin 🧁'`.
   - **Bypassed Hardware Web Speech Mic Block:** Standard browser-based SpeechRecognition is blocked by OS-level mic locking during active Gemini Live WebRTC sessions. To capture the user's side of the voice conversation, we implemented client-side parallel Float32 PCM audio accumulation directly inside `useGeminiLiveV7.ts`'s script processor.
   - **Silent Whisper STT Transcription:** When silence is detected, we compress the accumulated Float32 PCM samples into an Int16 WAV Blob and pass it to the parent via an `onUserSpeech` callback. The parent sends this WAV Blob to `/api/chat/voice` with `triggerLLM: 'false'`, transcribing the user's speech silently using the local Whisper service, committing it to the SQLite database, and instantly rendering the user's text bubble in the chat log.

## Key Learnings & Decisions
- **Optimistic State Locks**: When utilizing standard interval short-polling for real-time local network multi-device sync, we must always guard the local state against database overwrites during pending transactions. Locking out the polling loop while `isThinking` is true ensures a flawless, glitch-free local UI experience.
- **Double-Mic Parallel STT**: Since browser speech recognition threads are locked when active WebRTC/PCM streams (like Gemini Multimodal Live API) occupy microphone devices, we can tap into the exact same WebRTC stream data, buffer the PCM buffers while the user speaks, and silently transcribe them upon silence to record user voice history.
- **Unified Database Rooms**: All features (standalone pages, overlay panels, floating widgets) must share identical room definitions in the SQLite schema to allow fluid transitions.
